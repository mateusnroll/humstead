## Integration performance correction

The actual 2,000-asset/200-collection workload exposed unbounded eager view construction and repeated verification of identical shared audio during startup. Preserve every existing acceptance criterion and architecture bound; this revision adds only the implementation/proof scope needed to meet those already approved requirements. The prior valid approval and completed supplemental correction/follow-up remain historical evidence, not an exhausted review to retry.

Use native lazy rendering for optional ambience rows and large Downloads/Credits collections to avoid eagerly materializing the full library, with stable asset/collection identities and framework-managed prefetching and focused-row retention permitted. Preserve the compact player, all existing controls, native names/values, creator links, per-station/preset edits and reset semantics. No search, queue, new library feature, hidden asset truncation or lower limit. Offscreen rows must remain reachable by scrolling and keyboard/VoiceOver; prove first, middle and last asset access and focus visibility. Changes that make offscreen controls unreachable are failures, not acceptable virtualization.

Within each existing LibraryStore load/install/missing-assets verification operation, verify a shared file once per identical physical location and integrity contract (SHA256, byte length, codec and bundled-equivalent resolution). Reuse that result only inside the operation for every referencing asset; propagate a failed shared-file check to all affected asset IDs. Never persist or reuse verification success across operations, across content changes, or into playback acquisition. Playback acquisition retains fresh file-type/size/hash/codec validation, file leases and deletion safety. Unknown/corrupt manifests and audio retain existing preservation behavior. Do not introduce a cache service, schema migration, database, dependency or background daemon.

The primary native bounded workload proof in the existing performance criterion additionally records time to enabled controls, peak and settled resources, all2000assets/200collections reachable,16enabled layers and accessible17th rejection. Supporting real-filesystem tests cover shared valid blobs, shared corrupt blobs and different declared integrity metadata; bounded UI tests exercise offscreen keyboard focus and first/middle/last rows. Show failure on the preserved current implementation before correction, retain the existing42unit/11UI tests and all analytics consent assertions, then rerun focused and full verification. External incoming media pause commands remain genuine commands; never suppress them to manufacture a passing playback test. Physical/audio-quality gates remain pending until actual observation.
