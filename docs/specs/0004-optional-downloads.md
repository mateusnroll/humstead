## Scope and non-goals

Implement optional fixed-station collections and ambience packs through a small static-catalog client, transactional local library and native Settings Downloads page. Ship no unapproved audio or production endpoint. A release-injected HTTPS origin is optional and fixed for the built app; an unconfigured development build explains that online collections are unavailable and continues all local listening. Actual end-to-end download behavior is exercised through the same URLSession/file/audio path against a project-owned local HTTP fixture in the strict sandboxed Testing app. No cloud provisioning, public release, analytics, account, streaming, new stations, background download service, ZIP extraction, credentials, backend or self-update mechanism.

## Compatibility and migration

Target macOS13+ arm64, compile availability checks and runtime-test only this Mac. New library absence is empty, never blocks bundled listening. Unknown newer library/cache schemas preserve original bytes and disable affected mutation with a warning; no destructive fallback. Existing settings schema1 remains readable, and older bundled-only settings gain optional entries only through user actions. Removing optional assets sets unavailable optional entries to disabled while retaining each saved level and all bundled defaults. Settings validation retains well-formed unavailable optional IDs as disabled entries (bounded to2000distinct sound IDs), never enabling them or resolving them to files. Reinstalling a sound makes its retained slider level available but does not automatically enable it. Network and file operations are serialized in their owners; immutable snapshots/generation IDs reject late responses after cancellation, update, removal or shutdown. Keep at most200installed collections/2000distinct assets and bound each operation/catalog response as above; refuse an install exceeding those limits without discarding old content.
