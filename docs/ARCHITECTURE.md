## System and dependency boundaries

SwiftUI player, Settings and menu-bar views send typed actions to one MainActor application model. That model owns playback intent, selected station/preset and presentation state. Views never read files, create players or send network requests directly.

AudioController owns AVAudioPlayer instances on one dedicated serial executor, receiving ordered typed intents and publishing state back to MainActor: one current music player and one player per enabled ambience sound. Player creation, prepare/play/stop and file work remain on that executor: the inspected SDK explicitly documents synchronous hardware work in play/stop, even though playback streams asynchronously. Use file-backed players, prepare before starting, loop authored ambience through numberOfLoops, and advance music from completion callbacks. Start resumed players against a shared device-time deadline where supported; logical play/pause state is shared. Audio is always local: no streaming URL reaches a player. AVAudioEngine, custom DSP and a custom render callback are unnecessary for this v1. If real loop/memory proofs fail, revise this decision before introducing them.

SettingsStore and LibraryStore each serialize their own file mutations. DownloadCoordinator owns network tasks, temporary files, hash validation and atomic installs. Audio leases prevent removal of in-use assets until playback has safely switched or stopped. Completion callbacks carry a generation token; changing station, cancelling or disabling an operation invalidates old work before it can affect current state.

SystemMediaBridge registers MPRemoteCommandCenter play/pause/toggle/next and publishes MPNowPlayingInfoCenter metadata and macOS playbackState. It does not intercept global key events or control other apps. OS arbitration determines the active Now Playing app. Seek/previous commands are disabled. In ambience-only mode metadata names the station and ambience preset rather than a silent song; next is disabled until music is audible again.

AudioRouteObserver uses Core Audio default-output, device-alive and transport/data-source observations to detect the disappearance of the active headphones. On a relevant route event pause the whole mix; switching/reconnecting never clears the user-paused state. Post-change notifications alone do not establish prevention of a brief speaker leak. By explicit user decision, all hardware testing occurs at final integrated acceptance on this Mac, including output-route behavior with wired and Bluetooth headphones. Earlier milestones use deterministic route-event tests and keep this physical proof pending; those tests cannot establish absence of speaker leakage. If AVAudioPlayer can reroute before the app can intervene, revise to explicit output-device binding or a different native audio boundary and reapprove the architecture; do not weaken PRD-R-015. This remains a final acceptance gate, not a promise that current observation hooks suffice. Deferring the test accepts the risk of late audio rework, not a waiver of headphone safety. Do not port iOS AVAudioSession interruption assumptions into macOS.

UsageReporter accepts only closed semantic counters from application outcomes, including failed downloads. It cannot access track/source metadata or arbitrary error strings. Production network hosts are fixed at release build time; local testing uses injected transports and a local sink, with no public-service traffic.

## Data and interfaces

Inside the app sandbox container, Application Support/Humstead contains settings.json, library.json, catalog.json, Audio/<sha256>.<ext>, Staging/ and usage.json. No writes outside the container at runtime; no iCloud sync.

Settings schema v1: currentStationID, musicVolume, stationSettings keyed by station ID, selectedPresetID per station, and presetMixes keyed by preset ID per station. A mix stores stable sound IDs, enabled state and level 0–1. Preserve edits for every preset/station pair. Analytics choice is undecided/enabled/disabled; no installation ID exists. Save validated snapshots via atomic sibling replacement after a 250 ms debounce; flush on explicit quit within a one-second limit. If writing fails, show a nonblocking persistence warning. On invalid settings preserve the unreadable original, recover defaults and disclose that recovery. Unknown newer schema is read-only with defaults, not destructively overwritten.

Runtime playback position and sleep timer are not persisted. Relaunch restores configuration paused and restarts the current station's shuffle bag when Play is pressed. A shuffle bag covers playable installed station tracks; the first selection in a new bag differs from the last played track. Music volume zero pauses its player and freezes its position; ambience-only resume does not consume silent songs.

Original presets: Music Only enables nothing; Rainy Window enables rain at 0.35; Café enables café at 0.25; Fireside enables fireplace at 0.30; Forest enables forest at 0.30. Other layer sliders initially sit at 0.25 but are off. These normalized starting levels are provisional tuning values to audition against the actual mastered assets, not claims of equal perceived loudness. Reset replaces only the current station/preset mix. A removed downloaded sound is disabled in affected saved mixes and disclosed; all original presets remain intact.

Timer: disabled initially; 15, 30 or 60 elapsed minutes, cancellable or replaceable. Use ContinuousClock for the in-process deadline, including system sleep; observe wake and pause immediately if expired. Pause does not suspend the deadline. Fade the master playback gain over five seconds at expiry while preserving saved volumes, then pause. If already paused, simply expire. Quit clears the deadline. System sleep pauses audio; wake leaves it paused to avoid unexpected output (agreed by the user on September 20, 2026).

Catalog schema v1: schemaVersion, catalogVersion, collections[], assets[]. Each collection has stable ID, kind music/ambience, version, label, stationID when music, assetIDs and totalBytes. Each asset has stable ID, SHA256, byteLength, codec, duration, relative immutable path, title, creator, originalSourceURL, optional creatorProfileURL, license/version/URL, attribution text, modification notice and optional bundled equivalent. Remote data cannot define code, new station definitions, prompts, endpoints or arbitrary filesystem paths. Reject unknown schema, duplicate IDs, path traversal, invalid values or foreign asset hosts. Source/profile URLs are external links, never download URLs.

Enforce a 2 MB catalog response, 2,000 assets, 200 collections, 100 MB per audio file and 2 GB per collection. These are proposed validation/workload bounds, not promises of an initial catalog that large. Music is AAC-LC in .m4a, typically 192 kbps stereo; ambience uses loop-ready lossless .caf where compression introduces audible seams. Retain source/license evidence outside shipped runtime data, in repository asset provenance documents. Bundled minimum: nine curated tracks and four ambience recordings. No asset is accepted before human audition and license verification.

Refresh the catalog at most once per 24 hours while running, with conditional HTTP requests. Explicit Check for updates may refresh once per minute. Keep the last valid catalog on error; bundled and installed media do not depend on catalog availability. Download listings show only approved fixed stations and available ambience packs.

A collection is a set of individual immutable objects, not a ZIP. Deduplicate by content hash. Show both total size and missing bytes before confirmation. At most two simultaneous file transfers; 30-second idle timeout, ten-minute task bound, and at most two retries after 2/8 seconds for transient failures only. No retry for rejection, invalid content or insufficient space. Cancellation/quit removes partial staging; installed audio remains. Revalidate free space before starting and as data arrives; reject oversized responses. Only a fully verified collection manifest is atomically installed. During updates the old version stays usable until commit. Garbage collection removes unreferenced blobs after audio leases end. Approved behavior: explain the playback effects before deletion. Removing a playing optional collection first switches music to a bundled track in the same station, or stops only the removed ambience layers while other audio continues, then deletes unreferenced files. Bundled audio cannot be removed; optional packs can be downloaded again.

## Download hosting and emergency shutdown

Use one R2 Standard bucket and a production custom domain. Cloudflare currently includes five WAF custom rules on its Free plan; reserve one simple hostname/path Block rule, requiring no regex or paid plan. Immutable /audio/<hash> objects receive long-lived cache headers; /catalog/v1.json uses short caching; /control/v1.json is a small fixed schema containing downloadsEnabled and a revision. Serve control with Cache-Control: no-store and an explicit CDN cache-bypass rule; disable stale serving for it. The control document is not a general remote feature/configuration system. Never place R2 administrative credentials in the app.

Official clients require a successful control check no older than 60 seconds before starting each object. Failed/unavailable control checks prevent new downloads, with an accessible retry message; existing audio continues. During active downloads begin a control refresh no later than 50 seconds after the last successful response, with a five-second timeout; coalesce concurrent checks. Control age is measured by a monotonic clock, expires at 60 seconds, and must be rechecked after wake. Disabled, malformed, failed or expired control pauses admission and cancels pending/active app-owned transfers, removing partial files. Never poll while only listening. A fresh enabled response permits a user-requested retry; it does not restart a cancelled transfer automatically. Inactive clients learn the state before their next download. Client acceptance target while the process is running: stop transfers within 65 seconds after a changed control response is globally available, verified with controlled clocks and a real local transport; this is not an OS scheduling guarantee. Independently deny new starts when control is older than 60 seconds; CDN propagation before that point must be measured and is not a guaranteed SLA.

The operational shutdown also blocks /audio/ at Cloudflare's edge through a preconfigured WAF custom rule. r2.dev and all other public bucket aliases remain disabled; no public S3 credentials exist. This prevents direct asset access independent of client compliance. Keep control/catalog accessible so clients can explain the outage. Activation records rule deployment, tests known cached and uncached asset URLs, and verifies that denied requests do not fetch R2 objects. If the edge block is unavailable, disable bucket custom-domain access and verify denial as the fallback. Previously completed requests or already transmitted bytes cannot be recalled. An operator runbook and local fake-edge drill are built in v1; a real Cloudflare drill belongs to authorized provisioning before public release.

This is an emergency control, not an automatic dollar cap. No app-only flag can enforce behavior in modified open-source clients. Rate limits/retry limits bound cooperative traffic; an effective edge block stops new origin reads. Do not add a Worker, private-token broker or backend unless cloud verification demonstrates a necessary gap and architecture is reapproved.

## Analytics

Use PostHog Cloud EU direct ingestion via URLSession, with no SDK, cookies, device/session identifiers, autocapture, replay, diagnostics or server hash mode. Every weekly submission generates a fresh random UUID for the provider-required distinct_id, discards it immediately and never reuses or persists it. No identify/alias/profile calls; $process_person_profile=false and $geoip_disable=true. Project configuration discards stored IPs and disables enrichment. Network processors still observe source IP while handling requests; disclose that rather than claiming absolute anonymity. Do not interpret distinct IDs as users or installations.

Closed event humstead_usage_summary, schemaVersion=1, appVersion (release major/minor only), booleans usedAmbience/usedAmbienceOnly/usedTimer/usedMenuBar/usedDownloads, and bucketed downloadFailures (zero, one, two_to_five, six_plus). No station/preset/sound IDs, track names, artist links, durations, listening or action timestamps, hardware/OS versions or arbitrary properties. Provider receipt time remains observable. Reports describe opted-in reporting windows only.

Settings → Privacy offers off/on with full disclosure and no launch prompt. No collection before explicit opt-in. Start one local 168-hour accumulator on the first post-consent action; send on the next eligible active-app check after expiry. Consume and durably clear the accumulator before a single delivery attempt, never retry or flush on quit. If durable consumption fails, do not send. No backlog of missed weeks. Disabling immediately stops new collection/sends, cancels active requests where possible and clears local accumulator; accepted reports cannot be recalled. Local report state is bounded and contains no UUID. Re-enabling starts empty.

Ephemeral URLSession: no cookies, no credentials, no caching, no redirects, five-second timeout, fixed generic User-Agent, strict HTTPS host. Release-injected public ingest token only; no administrator key in source or artifacts. Fork/dev/test builds omit production configuration and use local sinks; analytics UI explains unavailability in such builds. PostHog Free currently allows 1 million events/month and states that usage stops at the limit without a card. Require a dedicated eligible $0 project/account with no chargeable billing configuration; if unavailable, production enablement stays blocked. Retention: one year, agreed by the user, with clear disclosure. No provider account creation or configuration occurs in this architecture phase.

## User interface and visual direction

Keep v1 deliberately simple; the user will polish the design later. The warm-neutral/amber/native direction is agreed, without an elaborate visual exploration or prototype. A single standard titled, resizable window, approximately 380×520 pt initially, with a scrollable ambience area when needed. Keep window chrome, standard menus and system focus behavior. Native SF typography and SF Symbols; warm neutral surfaces with one restrained amber accent, system light/dark appearance, semantic colors and increased-contrast support. The references inspire calm editorial restraint, without reproducing their artwork or an immersive scene.

Order: station selector; current title and clearly clickable creator; compact original-source/credits link; large primary play/pause and secondary next; music volume; ambience preset and Reset ambience; labeled sound rows with toggles/sliders; optional sleep timer. Settings separates Downloads, Privacy and Credits. No hidden hover-only controls. Credits enumerate music and ambience creators, license notices and source links; links remain readable offline even when opening the web is unavailable.

Use 120–180 ms native state transitions for disclosure/selection; no perpetual equalizer, animated background or timer-driven view redraw at audio frequency. Reduced motion removes decorative transitions. Space toggles play/pause only outside editing/control contexts; Command-comma opens Settings, standard close/quit work, and menu commands expose discoverable shortcuts. Slider keyboard behavior and VoiceOver values follow native semantics. Timer countdown updates no more than once a second while visible. Error/progress messages remain near their operation without disturbing listening or focus.
